# Security Policy

## Supported Versions
The maintainers may provide security patches or updates for current development versions of the project. Older versions are not guaranteed to be monitored or patched unless stated otherwise.

It is strongly recommended that users keep their deployments updated to the latest stable release to receive the most recent fixes and improvements.

## Reporting a Vulnerability
Use this section to tell people how to report a vulnerability.

If you discover a security vulnerability, please follow these steps:

Tell them where to go, how often they can expect to get an update on a
reported vulnerability, what to expect if the vulnerability is accepted or
declined, etc.

1. **Do NOT publicly disclose the issue.**
2. Contact the project owner privately at:
   - Email: 437render@gmail.com
3. Provide as much detail as possible:
   - Description of the issue  
   - Steps to reproduce  
   - Affected files or components  
   - Potential impact  
   - Suggestions for a fix  

You will receive acknowledgment within a reasonable timeframe. If the issue is verified, a patch or mitigation plan will be developed.

## Responsible Disclosure
All security reports should follow responsible disclosure principles:

- Give maintainers adequate time to address issues  
- Avoid exploiting the vulnerability beyond what is necessary to demonstrate it  
- Do not use discovered vulnerabilities for malicious activity  

We appreciate ethical researchers who help improve project safety.

## Security Expectations for Users
Users are responsible for:

- Securing their deployment environment  
- Running the software in a safe, monitored environment  
- Conducting additional audits and assessments  
- Keeping dependencies up to date  

This repository does not guarantee end-to-end security and should not be deployed in sensitive environments without additional protections.

## Out-of-Scope Issues
The following are generally **not** considered security vulnerabilities:

- Issues caused by user misconfiguration  
- Problems in third-party libraries not included directly in this repo  
- Deprecated features or unsupported versions  
- Social engineering attacks  
- Weaknesses introduced by user-modified code  

## Disclaimer
While good-faith efforts will be made to address security issues, the maintainers do not guarantee complete security or long-term support.
